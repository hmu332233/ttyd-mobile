# launcher

ttyd 터미널 주소를 저장해 두고 한 번에 열어 주는 정적 PWA입니다. 별도의 서버가 없으며, 모든 데이터는 브라우저의 localStorage에만 저장됩니다.

## 기능

- **목록과 열기**: 카드를 탭하면 해당 터미널이 열립니다. 자주 사용하는 터미널은 목록 맨 위에 고정할 수 있고, 나머지 터미널은 최근에 접속한 순서로 정렬됩니다.
- **접속 상태 확인**: 30초마다 각 주소에 요청을 보내서 응답 여부와 응답 시간을 표시합니다. 요청은 4초가 지나면 시간 초과로 처리됩니다.
- **필터와 검색**: 접속 가능 여부로 목록을 걸러내거나, 이름·호스트·메모로 검색할 수 있습니다.
- **등록**: 주소를 직접 입력하거나, ttyd 탭에서 **공유 → Terminals**를 선택하거나, 아래 형식의 `?add=` 링크를 열어서 터미널을 추가합니다.

  ```
  https://<런처 주소>/?add=https://mac:8443/&label=Mac
  ```
- **공유**: 카드 메뉴에서 등록 링크를 만들어 다른 기기로 보낼 수 있습니다.
- **백업**: 설정 화면에서 전체 목록을 JSON으로 내보내고, 다시 가져올 수 있습니다.
- **오프라인**: Service Worker가 앱 셸을 캐시하므로, 네트워크가 없어도 런처 화면은 표시됩니다.

UI는 [Vapor 디자인 시스템](https://vapor-ui.goorm.io)을 React 없이 사용합니다. 디자인 토큰은 `@vapor-ui/core`가 배포하는 공식 테마 CSS를 jsDelivr에서 그대로 불러오고, 버튼이나 시트 같은 컴포넌트 스타일만 `public/vapor.css`에 바닐라 CSS로 옮겨 두었습니다.

## 로컬 확인

```bash
npm run dev          # http://127.0.0.1:8090/
```

Service Worker는 https 환경에서만 등록되도록 제한해 두었기 때문에, 로컬에서 개발하는 동안에는 캐시가 개입하지 않습니다.

## 배포

```bash
npm run deploy       # wrangler pages deploy public --project-name terminals-launcher
```

처음 배포할 때는 `npx wrangler login`으로 한 번 로그인해야 합니다. 이후에는 배포할 때마다 `sw.js`의 `CACHE` 값을 올려야 이미 설치된 기기의 캐시가 갱신됩니다.

## 데이터

터미널 목록은 `localStorage["terminals.v1"]`에 배열 형태로 저장됩니다. 각 항목의 구조는 다음과 같습니다.

```json
{ "id": "…", "url": "https://mac.tailnet.ts.net:8443/", "label": "Mac", "note": "herdr", "color": "blue", "pinned": true, "lastUsed": 0, "createdAt": 0 }
```

## 제약

- 런처와 터미널의 오리진이 서로 다르기 때문에, PWA에서 카드를 탭하면 터미널이 커스텀 탭으로 열립니다. 뒤로가기를 누르면 런처로 돌아옵니다.
- "접속 가능" 표시는 HTTP 응답이 돌아왔다는 뜻일 뿐이며, ttyd가 정상적으로 동작하는지까지는 확인하지 못합니다. 응답 시간도 opaque 응답을 기준으로 측정하므로 참고 용도로만 사용해야 합니다.
- 런처는 다른 오리진의 방문 기록을 읽을 수 없으므로, 터미널은 위에서 설명한 세 가지 방법으로만 등록할 수 있습니다.
